# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Roblox game written in TypeScript with [roblox-ts](https://roblox-ts.com). `src/` is compiled by `rbxtsc` into Luau under `out/`, and Rojo syncs `out/` and `include/` into Roblox Studio. The compiled output under `out/` is never hand-written. `src/` also contains hand-written Luau (`init.client.lua`, `init.server.lua`, and `src/Shared/ModuleLoader/`), so edit `src/` only.

## Commands

- Install dependencies: `npm install`. Rojo 7.7.1 is pinned in `rokit.toml`; install it with `rokit install`.
- Build once: `npm run build` (runs `rbxtsc`, emits `out/`).
- Build on change: `npm run watch` (runs `rbxtsc -w`).
- Sync into Studio: `rojo serve default.project.json`, then connect with the Rojo plugin. This is not an npm script.
- Lint: `npx eslint src --ext .ts`. There is no lint npm script. The ESLint config is `.eslintrc` (legacy format, ESLint 8).
- Format: `npx prettier --write src` (config in `.prettierrc`: tabs, width 120, trailing commas).
- Tests: none. There is no test runner or test file in the repo, so there is no single-test command.

## Architecture

**Compile and sync pipeline.** `src/Client`, `src/Server`, `src/Shared` compile to `out/client`, `out/server`, `out/shared`. `default.project.json` maps them into the DataModel:
- `out/Server` → `ServerScriptService.TS`
- `out/Shared` → `ReplicatedStorage.TS`
- `out/Client` → `StarterPlayer.StarterPlayerScripts.TS`
- `include/` plus `node_modules/@rbxts` → `ReplicatedStorage.rbxts_include` (roblox-ts runtime, generated by `rbxtsc`).

The project file says `out/Server` and `out/Client`, but the current build emits lowercase `out/server` and `out/client`. Rojo's mapping works on Windows, which is case-insensitive. Keep the casing consistent if this moves to another OS.

**Realm boundaries.** `Shared/` is replicated to both client and server, so it must not depend on server-only or client-only code. Imports are rooted at `src/` (`baseUrl`), so write `import Disposable from "Shared/Classes/Disposable"` and `import Character from "Client/Classes/Character"`, not relative paths across realms.

**Bootstrapping.** `src/Server/init.server.lua` and `src/Client/init.client.lua` require `ReplicatedStorage.TS.ModuleLoader`, optionally call `ModuleLoader.ChangeSettings(...)`, then call `ModuleLoader.Start(script.Services)` or `ModuleLoader.Start(script.Controllers)`. The loader lives in `src/Shared/ModuleLoader/init.lua`. Each module in `Server/Services` and `Client/Controllers` is loaded through it, and each module's `Start()` runs in `LoaderPriority` order. Side-effect-only modules export `{}` (for example `LogService.ts`, `CmdrService.ts`). Long-lived controllers export a singleton instance (`CharacterController`). The `*.meta.json` files set a `LoaderPriority` attribute of 9999 on the logging modules, so logging is set up before other modules run. ModuleLoader settings can also be changed through attributes on the ModuleLoader instance.

**Cmdr.** `Server/Services/CmdrService.ts` calls `Cmdr.RegisterDefaultCommands()`. `Client/Controllers/CmdrController.ts` is the client side (`@rbxts/cmdr`).

**React UI.** Client UI is written with `@rbxts/react` and `@rbxts/react-roblox` under `src/Client/React/`. Components live in `Components/` (for example `StaminaBar.tsx`), and ui-labs stories live in `Stories/`. `Stamina` mounts `StaminaBar` into `PlayerGui` with `createRoot`.

**Inputs.** `src/Shared/Inputs/CharacterContext/` holds input-binding metadata (`*.meta.json`) for the character's input context.

**Character model (client).** `CharacterController` listens for `LocalPlayer.CharacterAppearanceLoaded` and creates a `Character`, then destroys it on `CharacterRemoving`. `Character` extends `Disposable` and builds every entry in the tuple registry in `Client/Classes/Character/Components/index.ts`. The registry currently holds `Stamina`, `MovementSpeed`, `JumpPower`, `Sprint`, and `StateMachine`. `CharacterComponentBase` lives in `Shared/Classes/` and is generic over the character type, so each realm passes its own (client components extend `CharacterComponentBase<Character>`). Each component receives the character in its constructor. `Character.GetComponent("Stamina")` is typed through the `ComponentMap` type. To add a component, write the class and add it to that registry. `StateMachine/States/` holds the state classes (`Idle`, `Walking`, `Running`) on a shared `CharacterStateBase`.

**Stats and modifiers.** A value that other systems can change through modifiers is a stat. Use one of two patterns:
- A single stat bound to a Humanoid property (for example `MovementSpeed` and `JumpPower`, or the maximum in `Stamina`): extend `StatComponentBase<Character>` (in `Shared/Classes/`), pass the character and base value to `super`, implement `Write`, and call `Refresh()` in the constructor.
- Several internal values that don't map to one property (for example `StaminaRegenerator`'s strength, rate, and delay): hold one `Stat` object per value. `Stat` lives in `Shared/Classes/Stat.ts`.

`Stat` exposes `StatChanged(oldValue, newValue)`, `ModifierAdded(id, modifier)`, and `ModifierRemoved(id)` signals. `StatChanged` fires only when the computed value changes.

Change a stat with `AddModifier(id, modifier)` and `RemoveModifier(id)` on the `Stat` (for a `StatComponentBase`, that's `component.Value`), using a stable id per source (for example `"sprint"`). Never write a bound property directly, because the next refresh overwrites it.

**Disposable pattern.** `Shared/Classes/Disposable` gives each object a `Janitor` and a `Destroying` signal. Register connections and signals with `this.Janitor.Add(...)`. `Destroy()` clears the table and its metatable, so the object cannot be used afterward.

**Logging.** `@rbxts/log` is configured once per realm, in `LogService.ts` (server) and `LogController.ts` (client). Classes get a logger with `Log.ForContext(ClassName)`. Message templates use named placeholders such as `"Loaded {Component} component"`.

**Ambient types.** `types/` holds global declaration files (`ReplicatedStorage.d.ts`, `Player.d.ts`). `tsconfig.json` has no `include` key, so TypeScript picks these up by default. Declare new Roblox instance types here as global interfaces.

**Networking and config (stubs).** `Shared/Remotes.ts` (`@rbxts/net`) and `Shared/Constants.ts` are empty. Define remotes in `Remotes.ts` so both realms share them.

## Gotchas

- `package.json` declares `@rbxts/t`, but no source file imports it yet. `@rbxts/react`, `@rbxts/react-roblox`, and `@rbxts/ui-labs` are in use under `src/Client/React/`. Check the code before assuming a dependency is in use.
- `src/Shared/` contains client-only and server-only scripts: `ModuleLoader/ActorForClient/LocalScript.client.lua`, `ModuleLoader/PersistentLoadedCheck.client.lua`, and `ModuleLoader/ActorForServer/Script.client.lua`. These are an exception to the realm rule above. Do not add more realm-specific code to `Shared/`.
- `tsconfig.json` sets `noLib: true` and takes its types from `@rbxts/types` (via `typeRoots`), so Roblox globals such as `game`, `Enum`, and `task` are typed without imports.
- `out/` and `include/` are gitignored generated output. Never edit them by hand; change `src/` and rebuild.
- The Studio output warning `ContentId: rbxassetid://203785492 failed due to: Asset type does not match requested type` comes from the Rojo plugin, not from project code. Ignore it; don't search the repo or Studio for that asset ID.
